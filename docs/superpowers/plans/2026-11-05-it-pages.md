# IT pages (Part B) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The IT Lead gets **IT setup** (To assign · In progress · Ready, a ring for today's setups, Assign staff and Mark ready); IT Staff get **My tasks** (their own setups, read only). Missed setups show on Ready.

**Architecture:** Backend: `GET /it/tickets` gains `from`/`to` (setup day = first session's day), `state`, `mine` and an item field `missed`; new `GET /it/tickets/summary` and `GET /it/staff`. Dashboard: `ReviewHead` becomes a generic head (title, line, ring parts, tabs) used by To review and IT setup; a new IT queue page reuses the To review row look; an assign pop-up in the Ledger style; My tasks reuses the IT rows read only. Roles, home, menu and waiting counts learn IT_LEAD and IT_STAFF.

**Tech Stack:** FastAPI, SQLAlchemy 2, MySQL, pytest; Vue 3 + TypeScript, vue-router, Pinia, vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-05-owner-and-it-pages-design.md` (Part B and "Shared").

## Global Constraints

- Schemas, routers and services: one file per resource; models: one class per file.
- No class names that clash with Tailwind utilities or `main.css` globals (`grid`, `table`, `flex`, `hidden`, `ring`, `border`, `shadow`, `switch`, `sheet`, …).
- Phnom Penh time. No new booking rules: only the IT Lead assigns (T10) and marks ready (T11).
- The Pitika and owner pages behave exactly as before (their tests pass unchanged).
- Commit messages plain, no Claude attribution lines.
- Gate at the end: `ruff check app tests`, `ruff format --check` on changed files, `pytest -q`, `npx vitest run`, `npx vue-tsc --noEmit -p tsconfig.app.json`, `npx eslint src e2e` (no new warnings), `npx playwright test`.

## Review Focus

1. **Missed setup:** a ticket RECEIVED or ASSIGNED whose meeting has started (booking may still be SETUP_IN_PROGRESS until the expiry job runs, or already CONFIRMED). It is on `done` with `missed: true`, never on `to_assign` / `in_progress`, not counted in `to_assign` / `in_progress`, and shows no buttons. Pinned in Task 1 and Task 4.
2. **IT Lead who is also IT Staff:** IT setup shows every ticket; My tasks (`mine=true`) only theirs. Pinned in Task 1 and Task 5.
3. **Assign with an inactive staff member** (turned off after the picker loaded): the API's 409 shows in the pop-up and the list reloads. Pinned in Task 4.
4. **Setup near midnight / day groups:** groups use `setup_date` (Phnom Penh), not the UTC date. Pinned in Task 3.
5. **No setups today:** ring "0/0" in light colours, line "No setups today · 2 to assign". Pinned in Task 3 and Task 4.

**Interfaces:**
- `GET /api/v1/it/tickets?state=to_assign|in_progress|done&mine=true&from&to` (plus existing `status`, `q`, `page`, `size`). `state` (422 on another value):
  - `to_assign`: `status = RECEIVED` and not missed; `in_progress`: `status = ASSIGNED` and not missed; both earliest first start first.
  - `done`: `status = READY` or missed; sorted newest first by `coalesce(ready_at, first start in UTC)`, then ticket id desc.
  - Missed = `status != READY` and the first start (local, `first_start_sql()`) `<= clock.now_local()`.
  - `from` / `to`: the first session's day (`first_day_sql()`) in range; `to < from` → 422 `fields.to`.
  - `mine=true`: only tickets with me in `it_ticket_staff` (also for an IT Lead).
- `ITTicketItem` gains `missed: bool`.
- `GET /api/v1/it/tickets/summary` (IT Lead only) → `ITSummary { to_assign, in_progress, ready_today, due_today, due_today_ready }`: counts of visible tickets; `to_assign` / `in_progress` leave missed out; `ready_today` = `ready_at` inside today's Phnom Penh day (UTC bounds as in `_decided_summary`); `due_today` = first day = today (missed included); `due_today_ready` = those READY.
- `GET /api/v1/it/staff` (IT Lead only) → `ItemList[ITStaffOut]` of active users with the IT_STAFF role, by `name_en`.
